# K AI Studio 战略方向 — 从参考图还原到 SketchUp 约束深化，再到完整设计交付

日期：2026-10-09。用户提供建筑学长 GPT-6 Astra 商业办公综合体演示的中文流程作为**产品愿景参考**（并非独立实测、开放源码或可复制的竞品性能证明）。

## 我们究竟应该借鉴什么？

演示链路：现有地形/用地红线 + SU 简易体块 → 上传建筑意向图 → 自然语言明确要求 → MCP 操控 SU 深化并可视化 → 更换参考图进行新方案 → 截图反馈并局部修复 → 继续增加构筑物 → 用地/层高/车位尺寸检查 → 后续 CAD、渲染、分析图、漫游、交互汇报。

真正值得借鉴的是**带可靠起点的、人在环路的三维方案深化**，而不是假设“GPT-6 Astra”或某个 MCP 自动解决了所有空间理解、规范、施工图、审美和交付问题。演示中的准确度、执行成本、工程落地能力未经我们的测试；其内容不赋予复制私有 Skill 或内部桥源码的许可。

### 两种任务必须分开

| 模式 | 初始条件 | 模型可推断的范围 | 当前状态 |
|---|---|---|---|
| **Image → SketchUp（当下主线）** | 一张/多张原建筑参考图，项目专属空白 SU | 未知背面/尺寸需要声明 estimated、approved inference | 已有端到端工程链路和真实 SU2024；视觉仍 PARTIAL |
| **Existing Mass → Design Development（下一里程碑）** | 用户自己的 SU 白膜/地形、红线、楼层/面积约束、设计意向图 | 必须**保护**输入体量、基地红线、用户已确认尺寸；允许修改的区域明确列出 | 尚未形成经验证的产品级工作流；**不能在本轮宣称可导入任意现有 SKP 并安全编辑** |

**架构缺口**：现有 `app/project_ruby.py` 的 guard 限定 `blank-disposable-*.skp` 路径，允许编辑**项目自己已生成的 owned root**，不等于用户任意在 SU 中打开的白膜 SKP 可安全被接管。将来的 Existing Mass 入口需要：原图/模型安全复制为项目拥有的 disposable working copy、模型/红线基线只读快照、版本/单位核验、修改授权与保护区域、方案分支和失误回滚。不得直接删除“blank-disposable”防护、对任意 active model 执行 Ruby、或者让第二个 ADAI MCP 与 Kongxing 并发写入。

**输入资料**：`app/reference_assets.py` 已区分 reference/site/brief 图像，`app/models.py` 存在 Site / Brief / DesignIR 和 `architecture_design` / `image_reconstruction` 等领域基础，**但这些 schema/素材分类不能当作完整红线/用地指标/消防/停车规范验收能力**。现阶段优先明确 KNOWN / ESTIMATED / INFERRED 和 owner approvals，后续再做硬约束求解和建筑法规核验。

## 阶段化路线

### P0 — 当前：先让 K AI Studio 真实建好建筑（本轮 Codex）

* 保留一个项目、一个 Kongxing writer、一个经主机批准的持久 Ruby/SKP 事实源。
* 使用可用的最高能力 Codex 建模模型，整合 ADAI 的**真实可调用** wall openings、loft/profile、shell/band 等几何手段（必须验证目标 SU Ruby 接口；不把已安装 ZIP 误认为质量提升）。
* 提升 reference-to-geometry 参数映射：floor/bay rhythm、开洞位置、幕墙与竖向遮阳线、屋顶/女儿墙拓扑、材质分区和比例。普通别墅先验证，不强行新增用户未给的商业办公体量。
* **近景截图 → 明确缺陷 → KEEP 局部修改 → 真截图重审**；专门抓已有 Sol Low 问题（墙顶水平拼缝、窗口比例、构件方块化、场地过大影响 framing）。
* 建模前 schema 契约自查/有限修复，阶段策略从 pending 到实际步骤，独立只读 Critic 能执行时才写 dedicated。
* 当前 GitHub 测试任务与上传规则仍优先：`docs/NEXT_NATIVE_TEST_GPT6_LUNA_MAX_2026-10-09.md`，`docs/TEST_EVIDENCE_PROTOCOL.md`。六张主机认证视图、runtime metrics/errors/真实 SKP reopen/edit、实际模型 ID 和是否 ADAI 被调用都要提交。**无需 DeepSeek vs ADAI 或建筑学长对照实验。**

**本轮退出条件**：真 Windows/SU2024、完整网站重建且质量诚实评估、ADAI 几何在目标 SU 中被实际调用（或报错/阻塞）、项目 SKP 可原生编辑/重开、保护对象没有意外回退、GitHub 证据可复查。不能把本轮代码 review 或 CI 等同真机验证。

### P1 — 安全种子模型深化 + 多方案（P0 稳定后）

* UI 支持选择 `从图片重建` / `在现有体块上深化`，输入场地红线、参考图、层高/体量/出入口等硬约束；一轮主要确认后持续操作。
* SU 现有模型通过用户明示选择与**项目级克隆副本**成为可写模型；将原体量、红线、用户设定尺寸做 semantic/provenance baseline 和不能改动的 KEEP。
* 按区域/楼层/外立面范围进行局部深化；设计用户截图指导修复，失败局部 rollback；build version 与 GUID/saved baseline 对齐。
* 支持从**同一白膜起点**建立多个方案分支而不是覆盖上一方案：`Variant A/B/C` 各自独立的 project-owned SKP 与 revision/preview。方案切换后可以继续独立编辑。
* 硬约束：红线/面积/建筑尺寸/层高/体量位置可以数值测量，并与“推断值”严格区分；不可把一张非标准红线截图当作精确 CAD 坐标。安全离线/权限/文件大小检查。

### P2 — 建筑方案图件与可视化（P1 稳定后）

* 真实 3D 模型生成标注**概念/方案级**平立剖图、尺寸表、总图/分析图；模型 provenance 和真实尺度可追溯；几何变更后图件有更新策略。
* 场景/天气/材质和多角度渲染，保证与**同一 SketchUp 几何**一致；避免每个视角图片独立生成不同建筑。
* 建筑漫游视频及可交互网页汇报，作为基于工程结果的输出，不替代工程真实性。
* CAD DXF/DWG“导出”不等于自动形成**合规施工图**；详细设计深度、规范、结构机电、尺寸、公差、消防、无障碍以及当地主管部门批准仍需专业核验。

### P3 — 完整设计协作与交付（远期）

* 多专业互操作、变更传播、关联平立剖、规范辅助、可审计模型版本、审批与专业签署/监管要求。
* 只有在具体场景内受验证才能使用“可直接交付施工图”等商业表述。

## 从竞品演示提取的产品原则

1. **用户先锁定空间事实，AI 再探索设计变量**。既有 SU 基线与红线约束降低纯图片重建的歧义。
2. **方案可以多版本探索，但每个版本始终是同一模型的真实可编辑对象**，不是混淆多个视角的 2D 图。
3. **边看边纠错，而不是全局重新生成**。屏幕截图是事实反馈，模型 diff、KEEP 与 writer receipt 是工程边界。
4. **AI 只负责选择方案和消除不确定性，SU/确定性代码负责坐标、体量、保存、测量和核验**。演示的层高或车位尺寸例子不代表所有城市/用途的法规都满足。
5. **先产品质量，再扩展展示功能**。当前不新增 CAD、渲染、漫游和 PPT 的执行任务，避免分散本次 Sol→高能力模型真实建模闭环。
