## 1. 本轮决策与授权

用户已明确要求从内部候选走向实际部署，并授权完成官网、后端、数据库、手机号验证码、微信扫码、个人 API 保存、平台 BAI 和商业收费闭环。不要停留在分析、再出一份规划或只交付静态展示网站。

本轮采用以下决定：

- **部署：腾讯云中国大陆上海 CVM + 现有 Docker Compose / FastAPI / PostgreSQL / Caddy；COS 分发安装包。** 已有获授权、符合这些条件的资源直接复用。4 vCPU / 8 GiB / 100 GB SSD 是小规模 Beta 的起始容量建议，不是已购买资源、价格或高可用承诺。没有预算时先完成代码与部署工件，不擅自购买。

- **首个收款渠道：微信支付 Native。** 保留 Stripe 代码；不要求本轮同时接入支付宝或海外收款。
- **模型：保留当前 Harness、SketchUp 桥接和可替换模型边界；首发平台供应商 BAI，BYOK 为高级选项。** 不重写 Agent，不用另一个更强模型掩盖首用问题。
- **支持范围：Windows x64 + 实际验收的 SketchUp 2024。** 其他软件、Mac、更多 SU 版本和海外版后续再做，不借未承诺兼容性拖延首发。
- **视觉：保留原 K 品牌、深绿／暖白／金色、衬线和客户端主布局。** 只修核心流程、状态与可理解性，不开展新一轮大改版。

已授权的普通工程、可逆配置、已有资源内的部署、分支提交和必要验收自行完成；不逐项找用户批准。涉及尚未给定的云采购预算、正式经营主体、对客价格、商户签约或付款人扫码等，统一进入负责人配置表。先完成所有不依赖这些输入的工作，再一次性交接确切缺项；不得因缺一个 Secret 停止全部开发。

## 4. 先搭好可交付的运行边界

云上只运行 `cloud.main:create_app`、`website/`、数据库和反向代理。桌面 `app.main`、Agent、SketchUp、MCP、用户模型留在用户电脑。桌面通过出站 HTTPS 访问云服务；不向互联网开放本机建模端口。

| 数据 | 首发保存位置与行为 |
| --- | --- |
| 身份、偏好、订单、余额、用量、云 API 连接 | 按 `users.id` 存 PostgreSQL；API Secret 加密且默认不可回显 |
| 平台 BAI Key、支付密钥、OIDC Secret | 服务端秘密配置；不进入浏览器、桌面安装包或日志 |
| 用户 BYOK Key | 用户明确选择“加密保存到我的账户”后进入云凭据库；授权设备同步后再由本机 DPAPI 保存 |
| 对话与项目 | 本机按账户隔离；云端保存任务及项目元数据。对话云同步明确选择开启，提供删除；不上传无关本地路径 |
| SKP、源图、素材 | 默认本地；首发不做任意大型原文件的自动云盘同步。不得把个人数据归属解释为静默上传全部模型 |
| 安装包／备份 | 安装包放专用发布 COS；数据库备份放独立私有位置，加密且访问权分开 |

单机首发保留一个应用 worker，直到限流等状态真正共享；别为了“商业化”先改成微服务。设置账号并发、全局并发、队列上限和费用上限；容量满时清楚拒绝或排队，不无界接单。

## 5. 实施 A：真实云部署与运营恢复

复用 `deploy/compose.yml`、`Dockerfile`、`Caddyfile`、`backup.sh`、`restore.sh`、`restore_drill.py` 和 `cloud/cli.py`。补一份可执行、可重复运行的运维脚本／runbook，至少包含 `check`、部署、健康检查、备份、恢复演练、应用回退；命令参数从实际代码导出，别写不存在的“万能部署命令”。

1. 核实已授权云实例／SSH 或云身份、域名 DNS 与备案状态，记录地区、非秘密资源标识。缺资源时完成镜像和配置模板，继续其他实现。大陆域名公开访问按腾讯云备案要求办理；不要写“测试站免备案”或把香港迁移当通用资质豁免。
2. 主机使用受支持系统与 Docker Compose；只公开 80/443，SSH 限制管理来源。Postgres 5432、应用 8920 和 MCP 不开放公网。检查现有 `172.31.91.0/24` 是否与宿主网络冲突；同步修正代理可信地址。
3. 精确固定部署源码 SHA 与镜像标识；正式 `.env` 为私有文件／密钥引用，检查只输出缺失项名称。不得打印展开后的完整 Compose 配置。记录迁移版本，修正 `/health/ready` 当前写死 schema 2 的判断，使之与真实迁移版本一致。
4. DNS 与证书就绪后在目标主机按下列现有顺序启动；有既存数据先备份，不能重建卷。演练健康检查、真实 HTTPS 流式请求、重启后持久化。
5. 配置 `cloud.cli recover-stale` 定时运行和 `cloud.cli audit` 定期核账。使用实际容器环境、服务账户和互斥机制；不能仅在文档写“设置 cron”就算完成。告警进入负责人已配置的通知渠道，通知不含客户内容或密钥。
6. 执行一次独立空库恢复演练；验证账户、订单、账本和凭据可解密。密钥备份独立受控，不能把 vault 主密钥和数据库备份公开打包。记录恢复命令和结果。

当前仓库已存在的启动顺序（前提：目标主机、生产配置和新增迁移已完成）：

```bash
cd deploy
docker compose config --quiet
docker compose build app migrate
docker compose up -d db
docker compose --profile maintenance run --rm migrate
docker compose up -d app proxy
docker compose --profile maintenance run --rm migrate python -m cloud.cli audit
```

可以先在获授权的受控环境部署候选并真实联调；通过后开放公众入口。不要用临时静态预览页声称数据库、短信或客户端已上线。

## 6. 实施 B：手机号与微信共用同一账户

复用 `cloud/main.py`、`cloud/auth.py`、`cloud/device_auth.py`、`app/cloud_account.py` 和现有桌面设备授权流程。

1. 创建／复用一个 Authing 正式用户池、一个 K Studio OIDC Web 应用。启用授权码 + S256、RS256/JWKS。Discovery 地址复制控制台实际值，不猜测 `/oidc` 或 `/oauth/oidc`。
2. Authing → K 的回调精确为 `https://实际域名/auth/callback`；微信 → Authing 的授权回调域按该租户官方配置填写。这是两个不同回调，不把微信直接送到现有 OIDC callback。
3. 托管页启用手机号验证码和 PC 微信扫码。主选 Authing 托管短信，核实实际套餐、额度、频控与公开商用开通状态；已有获批腾讯云短信可配置给 Authing，不额外开发第二套发短信 API。
4. 微信使用有登录权限的真实网站应用。账号身份关联选“询问绑定”，通过手机验证码证明归属。手机号先注册再绑微信、微信先注册再绑手机，两条路径最终必须回到同一 K `users.id` 和钱包。禁止昵称匹配或未经验证自动合并余额。
5. 保留稳定 `issuer|sub → users.id`；不以手机号当数据库主键。检查 `openid profile phone` scope，保留业务所需 email。新增可配置 `KSTUDIO_OIDC_TOKEN_ENDPOINT_AUTH_METHOD`，主选 `client_secret_post` 并与控制台一致；不得用 `none`。继续校验签名、iss、aud、state、nonce、过期及代码重放。
6. 官网入口写“手机号验证码 / 微信扫码”；桌面打开系统浏览器完成同一登录，再批准当前设备。区分“短信验证码”和“设备授权码”；授权成功提示回到客户端。Cookie / CSRF / refresh 轮换 / 设备撤销沿用并实测。
7. 新增账户页时精确扩展登录 `return_to` 允许列表，禁止任意外部跳转。未开通入口显示真实状态，不显示假二维码或固定验证码。身份关联采用托管页的标准 OIDC 流程，不改用 URL 传 ID token 的旁路。

## 7. 实施 C：账户 API 保存与个人数据隔离

现有本机 DPAPI 不等于账户云保存。补最小服务，沿用现有关系库迁移机制；不要另建一套用户系统。

| 建议位置（新增名可小幅调整） | 改动 |
| --- | --- |
| `cloud/provider_connections.py` | 当前账户连接 CRUD、授权同步、删除和审计 |
| `cloud/credential_crypto.py` | 使用成熟库 AES-GCM、随机 nonce、密钥版本、轮换 |
| `cloud/db.py` | 增量新增连接／必要同步元数据表；保留原用户、订单、钱包 |
| `cloud/config.py` / `cloud/main.py` | vault 配置验证、认证路由、schema readiness |
| `website/` | 我的 API、偏好、用量、订单、设备、删除入口 |
| `app/cloud_account.py` 与现有连接管理 | 授权恢复、DPAPI 按 K 账户分区、切换账户清理激活状态 |

连接最少字段：`id, user_id, label, provider, protocol, base_url, model_id, ciphertext, nonce, key_version, created_at, updated_at, last_verified_at`。列表只返回元数据、掩码、`has_secret` 和验证状态。

拟新增 `GET/POST /api/account/connections`、`PATCH/DELETE /api/account/connections/{id}` 与显式同步接口。每次查询由认证会话限定 `user_id`；请求体中的账户 ID 不作为授权依据。密文关联数据绑定用户、记录和格式版本。主密钥独立于数据库，设计版本轮换；先用受保护服务端密钥即可，不强制首轮搭完整 KMS 平台。

同步要求：当前用户主动确认同步到已授权设备；使用短时、一次性、绑定该用户和设备的授权，敏感操作要求近期身份验证。只有该设备受控 HTTPS 响应可取得 Secret，并 `Cache-Control: no-store`；普通网页列表、localStorage、反馈包和日志不回显 Secret。设备撤销／连接删除后阻止后续云获取，并在下次联网清除对应缓存；已经拿到 Key 的设备不能被声称“远程彻底抹除”，供应商撤销需用户操作。

BYOK 继续本地直连所选供应商；云端保存配置不意味着服务器访问用户任意 Base URL。连接探测由本机执行，显示目的域名，不绕过 TLS；不要顺带造开放代理。平台 Key 永远不进入此同步接口。

将本机 workspace、会话和凭据按 K 账户隔离。原匿名／作者 profile 单独保留，只有本人明确选择后才导入；A 登出、B 登录不能自动继承 A 的模型历史、Key 或激活连接。应用内隔离不能宣称同一 Windows 用户获得了操作系统级文件保密。

更新“网站不收集第三方 Key / Key 只在本机”的旧文案，使其准确区分本地保存与自愿云保存。提供连接删除、账户数据导出／删除及财务记录的实际保留说明，不伪造法定保留年限。

## 8. 实施 D：把已验证的 BAI 接到真实平台路径

复用 `cloud/gateway.py`、`cloud/ledger.py`、`app/cloud_account.py` 和当前 Harness provider adapter。作者 BYOK 已成功，不等于桌面 → 公网 K 网关 → BAI 也成功，必须补这一条实测。

1. 将正式 BAI Key 放服务端，用 `KSTUDIO_CLOUD_MODELS` 的 `key_env` 引用。正式 Base URL／模型 ID 以 Alan 实际账户可用值为准；公开 BAI 文档示例不能代替已购账号验证。
2. R2 实测路线为 BAI 标称 DeepSeek、Responses、Low；以真实证据和当前模型列表核实，不能被旧模板的 Completions / High 覆盖。客户端协议名与云配置 `responses` 做明确映射。记录供应商模型标签，不声称独立证明底层模型身份。
3. 平台服务端强制模型 `enabled && verified && prices_confirmed`，不能仅让 UI 显示 verified、后端仍接受未验收模型。未验收配置只在隔离的管理测试环境可用；通过后再开放公众。
4. 真实测试图像输入、工具循环、流式事件、取消和多轮编辑。检查 Caddy 实际流传输；当前网关请求上限 120 秒按实测区分连接／首字节／流空闲／总时限，必要时可配置但仍有界，不因一次任务耗时长就取消所有超时。
5. 不静默换供应商、自动路由模型或互换平台／BYOK。认证、额度、限流和上游故障分别给出可恢复提示。已发出请求或已开始流式响应后不整段盲重试；原生提交未知时先只读核对，不能重建一遍。
6. 保留服务端预占、幂等与结算。一个用户可见建模回合中的多次模型请求共享总预算／关联 ID；别让每次请求重置任务预算。用量未知进入待核账，不能填 0；管理员可审计处理。
7. 分开记录用户零售价和上游成本。BAI 缓存／时间段等价格以实际账户与官方当前规则核实；请求用量不能直接声称已经对上供应商账单。无账单的费用标注估计／待核，不再靠多跑任务“证明省钱”。

普通新用户默认看到“使用 K Studio 平台模型”，登录并取得已配置额度后直接进入连接指引。BYOK 进入高级选项；已验证 BAI 提供预设，只填名称与 Key，其余能力项按需展开。

## 9. 实施 E：真实充值与可解释的收费

当前 `cloud/payments.py` 只有 Stripe。新增最小微信 Native v3 adapter，复用订单与整数账本；不新造金融账户平台。

1. 配置真实 MchID、Native 权限、已授权绑定的支付 AppID、API v3 Key、商户签名与微信公钥／平台证书。**微信网站扫码登录 AppID 不自动等于支付 AppID。** 实际支持类型以官方商户申请为准。
2. 服务端根据已确认套餐创建订单和 `out_trade_no`；浏览器收到支付二维码／订单状态。人民币按元展示，如 ¥9.90；内部仍按分和整数额度记账，不能向普通用户输出“最小货币单位”。
3. 验签并解密回调，核对商户、AppID、订单、金额、币种和交易状态。对已验证事件先可靠持久化，再幂等入账；进程中断可重放恢复。回调成功响应不能早于可靠保存。前端返回页不是付款凭证。
4. 漏回调通过官方查单恢复；同订单、重复／并发回调最多入账一次。实现超时关闭、退款申请／查询与审计；部分退款和已消费余额冲突可进入明确人工核账，不强行写成已自动退款。
5. 新增的支付路由、配置与 `public/config` 必须按实际 provider 返回真实状态，不能继续硬编码 Stripe 或把微信生产 Key 套进 Stripe 的 test-key 规则。微信旧 v2 仿真环境不能当 Native v3 真实收款证据。
6. 对外价格须由负责人确认版本后启用：平台模型费与 K 服务费；BYOK 模型费由用户向其供应商支付，K 只收明确公布的软件服务费。沿用现有 BYOK 授权机制，用服务器可核验的服务授权单位收费，不凭客户端上报 Token 假装测得第三方账单。首发不做复杂防破解或保证本地软件绝对不可绕过。
7. 每次执行前显示付费主体、收费规则、预算、取消／失败处理；官网有订单、用量和待核账状态。实际小额支付与退款验证由授权账户持有人完成，工程师不得代填未知资质或代替用户扫码付款。

支付、平台建模、下载、注册各自有服务端开关。缺商户时可继续联调／明确免费试用，但最终交付必须写“充值未完成”，不能把赠送额度计为商业闭环已完成。

## 10. 实施 F：公众安装与首次建模界面

沿用 `scripts/build_desktop.ps1`、现有 launcher、冻结更新器、版本槽、DPAPI 与桥接；核实仓库其他构建入口后复用。添加一个成熟的 Windows 安装外壳，例如经许可核实的 Inno Setup，包含完整运行文件、图标、卸载及修复；不要把 70,449 文件内部 ZIP 让普通用户自己搬文件。卸载默认保留个人数据，可另行明确选择清除。

用户主路径为：官网 → 双击安装 → 打开 K Studio → 系统浏览器登录／授权 → 选平台模型或 BYOK → 检查 SketchUp → 安装／启用桥接并按需重启 SU → 选择目标窗口／安全练习副本 → 讨论和确认 → 建模 → 修改 → 下载／保存／重开。

公开流程不能要求用户安装 Codex、Python、Node、Docker，不能用 PowerShell、Ruby 控制台或手改配置补正常首用。原诊断脚本保留给支持人员。关键界面应显示当前账户、余额、模型来源、目标 SU 文档、进行状态和下一步，不展示开发栈术语替代操作指导。

发布前完成：

- 冻结实际版本与源码；核对完整包包含官方运行时、桥接和必要依赖，不带作者 Key、旧项目、私人模型或测试账号。
- 准备正常生产代码签名和独立生产更新信任；内部测试更新签名不能冒充生产信任。安装包签名与更新清单签名是两项不同验证；不能要求用户关闭系统防护。

## 12. 开放、回退和最终交付

商业 Beta 须全部核心条件真实通过，再使用冻结版本开放下载、已验收登录、平台服务及收款。若仅商户等待、其他条件已通过，可先开放明确的限量免费 Beta：关闭真实充值与收费入口，公示试用额度，赠送额度仍正常计量、预占、扣减且有总上限；只暂缓支付验收，其他核心门槛不豁免。此时继续推进收费接入，不能把商业闭环写为完成。两种状态都保留 Beta 标识、支持范围和容量限制；不是承诺所有人／所有软件／任意 API 都适配。

故障回退按独立开关处理：账户／密钥问题暂停相关授权；重复入账暂停收费并核账；原生误写暂停该版本建模与分发；BAI 故障暂停新平台任务；应用失败切回上一镜像。**应用回退不得直接恢复旧数据库覆盖新订单，客户端回退不得清空用户模型。** 数据迁移优先向后兼容／向前修复。

Codex 必须交付并推送：

1. 实际运行的网站 URL、账户页、下载页、状态页；若尚不能公网访问，明确写未部署及具体缺项。
2. 源码 SHA／镜像标识／安装包版本、大小、SHA256、生产签名与更新信任结果、公开下载位置。
3. 手机号、微信、平台 BAI、BYOK 云保存、真实充值、退款、首次建模、重开的逐项真实状态。
4. 最小验收证据、首次使用卡点及修复；累计真实或未知费用；剩余非阻断限制。
5. 已实用的部署／备份／恢复／查单／核账／关闭收费／回退操作及负责人的安全凭据引用。
6. 更新 `docs/CURRENT.md`、`docs/CURRENT_TASK.md`、`docs/HANDOFF.md` 与新的 release record，提交并推送实施分支、创建可审查 PR。历史失败不改写为 PASS。

结束时只能按事实选择：**商业 Beta 已上线**、**公开免费 Beta 已上线但收费未完成**、**部署候选已完成但外部资源阻塞**、或**工程尚有明确阻断**。只给 MD、只跑本地测试或只发布官网页面，不能选择第一项。缺外部资源时先交付其他全部可完成工件，再一次性给配置表，不能无限循环等待，也不能伪造成功。
