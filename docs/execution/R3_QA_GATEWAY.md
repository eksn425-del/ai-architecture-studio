# R3 gateway engineering verification — 2026-11-07

This is deterministic local engineering evidence, **not** a deployed BAI gateway or paid production acceptance.

The request route now requires the platform switch, a model explicitly marked `enabled=true` and `verified=true`, and confirmed prices. `X-KStudio-Turn-ID` is mandatory and persists across the desktop's visible turn. Each HTTP attempt still has its own idempotent task receipt; the stable turn ID binds cumulative cost, request count, original model/price, and expiry. The first accepted turn policy is persisted inside each task's existing `price_json`; later requests cannot increase that policy. Unknown usage counts the full reservation and still blocks the account pending reconciliation. Current SDK code must propagate the header; an unmodified older client fails before dispatch.

Server model configuration accepts `turn_budget_units`, `max_turn_requests` (default90), `turn_timeout_seconds` (default3600), and `timeouts` with `connect` (default10,max30), `read` (first response/stream idle,default120,max600), `total` (default900,max1800). Values remain bounded; keepalives cannot avoid the total deadline. The turn budget defaults to one request's reservation if not explicitly configured, rather than an unlimited loop. Prices, budgets and served model identity still require operator validation; no hidden effort/model substitution is introduced.

Global admission happens atomically with reservation: PostgreSQL advisory transaction lock, SQLite serialized writer lock. The configured number of reserved/running platform requests is bounded, with a clear429 before dispatch when full. No unbounded request queue exists. Per-account active/pending-reconciliation exclusion remains. Maintenance stale thresholds must exceed the configured maximum total upstream deadline to avoid declaring a live request dead.

HTTP401/403,402,429 and other upstream failures now return distinct categories and safe messages without echoing private upstream diagnostics. Timeout is distinguishable from connection/configuration failure. No automatic replay occurs. An upstream error event followed by DONE cannot be billed as successful completion; known-token validation rejects malformed/overflow values. Unknown usage remains null/pending rather than fabricated free usage.

Initial targeted run: **35 passed,25 skipped** across `test_r3_gateway.py` and `test_gateway_recovery.py`. Skips are the explicitly unconfigured disposable PostgreSQL fixture; PostgreSQL concurrency is not claimed as live verified by this SQLite result. Covered cumulative budgets after reconstructed engine, replay/conflicting turn, policy freeze, expiry, concurrent reservations, shared capacity, unverified model rejection, Responses tool-loop correlation, error categories, unknown receipts, no retry, and keepalive total deadline. Subsequent integrated runs supersede counts without rewriting failures. No paid provider call was made by this test.

Production remains blocked until real HTTPS/Caddy streaming, platform BAI, database/restart/restore, account isolation and authorized billing acceptance are actually run. The public R2 BYOK evidence is not a substitute for that new route.
