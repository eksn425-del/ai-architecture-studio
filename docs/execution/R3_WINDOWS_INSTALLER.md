# R3 Windows installer engineering — 2026-11-07

The mature installation shell is NSIS3.13, using its zlib compressor. The upstream [license](https://nsis.sourceforge.io/License) and [scripting reference](https://nsis.sourceforge.io/Docs/Chapter4.html) were checked. The supplied compiler ZIP was verified by the parent task (`ba63dffc4410ee89193e1cb5a41989991bd77c61068da17e3156d136b7b0b3d8`). The compiler is a build tool, not a runtime prerequisite for users. Its COPYING text is included with the installed product. This does not clear licenses for the entire frozen application.

`scripts/build_installer.py` inventories the actual frozen bundle, rejects links, private credential/model extensions and missing runtime/connector/native guard files, and generates exact NSIS payload/uninstall commands. It never embeds a user's data directory. Outputs must go to a new directory outside the bundle. The compiler produces one setup EXE and a size/SHA256 receipt. It always labels this build **unsigned internal candidate / public_release_ready=false**; code signing and public distribution clearance must be performed and separately evidenced before enabling a public download.

Normal install is per-current-user, no administrator elevation, fixed `%LOCALAPPDATA%\Programs\KStudioR3` with an independent `%LOCALAPPDATA%\KStudioR3` profile. Existing R2 installations/profiles are untouched. Windows x64 is required. No Python, Node, Codex, Docker, Ruby command entry or editing JSON is required of the installing user. The application still checks its actual WebView2 and legal SketchUp prerequisites.

The start-menu shortcut uses the existing stable version-slot launcher and `current.json`. A desktop shortcut is optional rather than silently replacing the owner's R2 icon. The final candidate refuses same-version overwrite (exit 6); installing a higher sequence into a new slot preserves older slots. A recorded highest sequence rejects older installers. Installing into an unrecognized pre-existing directory or a linked path is rejected. Uninstall uses only the generated exact file list and nonrecursive empty-directory removal; unknown files, older rollback slots, the separate profile, and tiny ownership/high-water records are retained. Those records let later reinstall recognize an intentionally retained installation. It never recursively erases a user-selected folder or profile. Removing personal data is not part of this installer.

Engineering fixture tests are distinct from application delivery: the fixture used a harmless Windows executable and a marker text, **not the actual R3 application**. Historical pre-hardening fixture compile/install/repair/upgrade/downgrade/uninstall completed; payload repair restored its SHA before that overwrite path was disabled, downgrade returned3, and uninstall retained a profile sentinel, unknown file and earlier slot. An initial silent downgrade displayed a modal instead of returning; the installer was corrected with explicit silent defaults and the failure preserved in the receipt. Five deterministic source/bundle safety tests also passed. A full frozen R3 bundle compile, clean Windows installation and native modeling are separate acceptance items; do not relabel the fixture as them.

Example once a reviewed frozen R3 bundle exists (all paths are operator-supplied):

```powershell
python scripts/build_installer.py --bundle <frozen-KStudio-directory> --output <new-E-drive-job-output> --nsis <verified-NSIS-directory> --version r3-internal-01 --sequence 8 --source-sha <full-source-commit>
```

## Runtime exclusion and pointer failure verification

The installer and uninstaller hold a native named installation mutex and exclusive Windows handles on both the installation-root launcher lease and profile `desktop-instance` lease. These conflict with the real launcher's and application's existing byte-lock handles. Active application, launch, update or concurrent installation is refused with exit **5**; silent mode has no blocking dialog. Root ownership is checked before creating the first root lease, so initial installation does not falsely classify its own lock directory as a foreign installation. Program-root ancestors retain strict reparse checks. The profile permits an intentional directory junction to the user's data drive because no profile deletion is performed; only the final lock file itself is forbidden from being a reparse point. A real fixture profile junction and its physically shared byte lock were tested, rather than assuming that behavior.

`current.json` is flushed to a same-directory temporary file and published with Windows `MoveFileEx(REPLACE_EXISTING | WRITE_THROUGH)`. A failed replacement preserves the old pointer. High-water is updated only after publication; downgrade protection reads both it and `current.sequence`, so interruption between the two cannot enable an older installer. An interrupted first extraction may be resumed only with this product's ownership marker.

Real compiled engineering fixtures (six tests passed) verified profile byte-lock installation/uninstallation refusal, two simultaneous installer processes, and a Windows deny-delete handle deliberately preventing pointer replacement. The latter returned **4**, preserving both old pointer and high-water bytes; unlocking allowed completion. Artificially restoring the older high-water still caused downgrade rejection (**3**). An initial test incorrectly quoted NSIS `_?=` and observed the parent uninstaller stub's zero exit rather than its detached child; the harness was corrected to use the documented unquoted trailing path, then both refusal and unchanged files were verified. This test failure is retained, not represented as a product success.

**P1 unsafe repair path removed:** final candidate refuses an existing owned version slot with exit **6**, before any payload or pointer write. This includes an incomplete slot left by extraction failure. The operator must use a newer build/slot; the previous accepted slot and personal data remain intact. The earlier overwrite-based repair described above is historical fixture behavior, not final candidate behavior. Transactional same-version repair is not implemented, and the receipt reports `same_version_repair_crash_atomic=false` plus `same_version_overwrite=REFUSED_EXIT_6`. A staging-slot repair design remains required before offering repair as a feature. The real final fixture additionally verifies byte-for-byte unchanged accepted and incomplete payloads when both retries are refused.

Local engineering evidence: `installer-fixture/lock-atomic-junction-receipt.json` under the R3 launch job (previous lock-only and safe-slot receipts retained). The first full compile was cancelled when this profile-junction correction was identified, with its log and cancellation receipt preserved. The final output is `installer-r3-final`, compiled from the unchanged audited frozen bundle; the manifest SHA, complete file set, sizes, modification times and absence of new reparse points were rechecked before reusing content hashes. Its receipt separates the frozen core commit from packaging input hashes and dirty-source status. Code-signing, component-license clearance and public-download gates remain closed. The registered quiet-uninstall command uses the final unquoted NSIS `_?=` parameter, preserving the actual uninstaller's refusal exit code; invoking the raw uninstall stub without that parameter can return zero before its detached worker finishes, as documented by the observed test correction.

The initial full compiler inherited the tool's C-drive temporary directory. This was discovered during compilation and recorded rather than repeatedly restarting it. Only that compiler's identified temporary file may be cleaned after the process closes. The builder is now fixed to pass `output/temp` as subprocess-only `TEMP`/`TMP`, leaving global environment variables unchanged; a further real fixture compile verifies the corrected scoped-temp path. The final build receipt records this one-run deviation separately from the corrected future build behavior.

## Full-bundle long-path failure and correction

`installer-r3-final` genuinely failed while reading an official DSH inspector Markdown file with a source path over MAX_PATH; its FAIL receipt and compiler error are retained. No SDK component was deleted. The original compiler's identified temporary file was automatically removed when it exited. The corrected candidate is **`installer-r3-final2`**, using E-drive process-local temporary files.

The [NSIS manifest documentation](https://nsis.sourceforge.io/Docs/Chapter4.html) says `ManifestLongPathAware` alone depends on a Windows system policy. No policy or registry setting was changed. Instead, audited payload source paths, extraction destinations, exact uninstall paths and ancestor-attribute checks use the [Windows Unicode extended-length path](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation) prefix. This preserves the original directory layout and installed root.

Actual compiled fixture verification covers a **291-character source** and **322-character installed file**, compares its exact bytes/SHA, and verifies uninstall removes the deep payload while retaining unknown files and profile data. A separate minimal NSIS probe with `ManifestLongPathAware false` also extracted a 392-character target. `tests/test_r3_installer.py::test_real_deep_path_install_and_uninstall` reran the real install/uninstall successfully. Local receipt: `installer-fixture/deep-path-receipt.json`. The full bundle must still compile and undergo independent real installation; this regression is not a substitute for that acceptance.

## Owner-selected E-drive production package preparation

The production builder now accepts paired `--install-root` and `--profile-root` options, independently of engineering fixture mode. These must be literal local drive-qualified Windows paths: root directories, UNC/relative/traversal paths, reserved or ambiguous names, NSIS/command quoting characters and overlap with each other or build inputs/outputs are rejected. Existing aliases are resolved for overlap checks; the NSIS program-directory reparse guard and fixed destination remain unchanged. Omitting both options preserves the generic per-user package. Public receipts identify only `selected-local-fixed-root`, never the selected private paths.

The installed launcher sets `TEMP` and `TMP` to the selected profile's `temp` directory before starting the application. This affects only the launcher process and inherited child environment, not Windows account/global settings. The original installation byte lease remains held during startup. A real Windows PowerShell test observes the chosen paths, hidden child launch arguments and active byte lease while intercepting process creation; it does not launch a fixture executable or touch the user's installation.

Targeted regression: **35 passed, 2 skipped**, with process-local temporary files and pytest output on E. The two skips are the existing explicitly enabled full NSIS fixture tests, whose earlier genuine runs remain recorded above. Private source/log/JUnit receipt: `install-roots-regression-receipt.json` in the R3 launch job.
