# 第一次使用 K Studio 建模

## 当前交付方式

优先使用 Windows 本地工作台：它复用同一个网站界面、Agent 和 MCP，在本机保存输入和模型。当前机器可以双击本地构建的 `runtime/desktop-dist/KStudio/KStudio.exe`；整个 KStudio 文件夹必须保留，不能只复制 EXE。也可以打开正在运行的 `http://127.0.0.1:8000/`；仓库开发脚本默认端口为 8787。

这是本地测试版。桌面壳不捆绑 SketchUp、Codex 登录凭据或未获许可的 Kongxing 插件。换到新电脑仍需配置连接器；目前尚不是一键安装即可收费的正式发行版。

## 用户只需要做这六步

1. 点击 **新建建模会话**，起一个名字。
2. 把图片粘贴进聊天框（Ctrl+V）、拖入页面，或点击 **图片 / 文件**。同一建筑可传最多 8 张参考图。任务说明、场地也从同一入口上传，检查缩略图和文件名。
3. 输入普通中文，例如：**「请根据我给的图片、任务说明和场地，帮我做一个 SU 模型。先看看还缺什么信息。」** 点击发送。根据 AI 提问继续交流；不需要写专业 prompt，也不需要此时连接 SU。
4. 回答关键问题后，AI 自动整理建模计划；也可以点击 **信息已确认，整理建模计划**。检查层数、尺寸、估算、推断和范围。点击 **修改参数** 可以继续调整；这些步骤不会改动 SU。
5. 开始建模前点击 **连接 SketchUp**，按教学保存、关闭其他模型，安装并启动现有 Kongxing 插件，检查连接，再点击 **打开独立模型并连接**。当前已配置的机器会启动独立 SU 文件；连接成功后点击 **批准计划并开始建模**，或在计划形成后发送「已确认，开始建模吧」。提问、否定、修改参数不构成批准。
6. 观察真实阶段、等待时间、工具调用和模型提交状态；有截图后可以查看模型面板。完成后点击 **下载 SKP**，打开检查。继续输入 **「检查背面和侧面，修好窗边，保留已经完成的细节」**，Agent 会在同一项目模型中修改。

原始私人模型不参与此流程。SketchUp 出现保存提示时，应保存或关闭自己的文档，再回到连接教学继续。不要在一次回合运行中手动打开其他 SU 文档、重复提交或刷新。

## 文件和网址到底能读什么

| 输入 | 当前处理 | 需要用户补充的情况 |
|---|---|---|
| PNG/JPG/WebP/GIF/BMP/TIFF | 规范化为图片并送入视觉模型；动态图取第一帧 | 图片不清楚时补清晰原图 |
| DOCX、TXT、MD、CSV | 提取可读文字进入对话上下文 | 文件本身没有文字 |
| PDF | 提取文本层 | 扫描件请补页面图片；当前不承诺 OCR |
| DXF | 现有 DXF 场地分析器读取边界/单位 | 单位、尺寸或边界不明确时说明 |
| DWG | 保存并明确提示未解析 | 提供带尺寸 PDF/图片或导出 DXF |
| 公开网址 | 直接粘贴聊天；有界、安全地读取网页正文 | 登录页、脚本页面或不可读网址请补截图 |

附件和网页是资料，不是可执行指令。当前重点仍是参考建筑复刻；复杂任务书/规划/规范合规并未通过本轮实测。

## 选择模型或自带 API

点击 **模型 / 自带 API**。预设 **GPT-6.1 Sol Low** 依赖本机 Codex 登录；自带 API 不需要这个登录。智谱国内平台请选 **智谱 GLM-5.3-Flash**，地址自动填为 `https://open.bigmodel.cn/api/paas/v4`，默认推理为 High；GLM 当前提供 Low / High / Max，没有 Medium，因此中间档使用 High；国际 Z.ai 是另一个选项，两者 Key 不通用。DeepSeek 也有独立选项。其他供应商可选 **使用自己的 API（LiteLLM）**，填写供应商模型标识、可选 HTTPS API Base 和 API Key。同一个提供方、模型和地址只修改推理档位时，可留空 Key 复用当前连接。Key 只保存在本机服务内存，关闭/重启后需要重填；不会写入项目、浏览器本地存储或 Git。

使用 API 会把本项目的图片/文字发送给该供应商。模型需要支持视觉和工具调用。2026-10-02 国内 GLM 已真实返回图片分析，并通过工具写入、修订参数卡；这还不代表建模质量合格。请检查计划里的层数和尺寸，AI 可能误读图片。不同供应商的最终建筑质量还没有逐一验证。切换提供方会重建 Agent 线程，但保留同一项目的参数卡、Ruby 和模型。

## 当前速度与效果

新人测试只用一张图、任务 TXT 和 30×30 米 DXF。两次交流分别约 145/165 秒，计划约 207 秒，首次建模约 477 秒。因此进度是实际事件与耗时，不是虚构百分比。模型可以编辑，外观细节、材质与真实效果图仍有差距，估算尺寸和背面不能视为实测结果。

## 本地桌面开发和连接器配置

开发者安装 `requirements-desktop.txt`，运行 `scripts/desktop.py` 或构建脚本 `scripts/build_desktop.ps1`。桌面数据默认位于本机应用数据目录的 KStudio/runtime，与仓库私有实验分离。

独立连接器可通过应用数据目录 KStudio/bridge.json 提供已有 MCP 的 command、args、可选 env/cwd。环境变量 `ARCH_STUDIO_MCP_CONFIG` 也可指定配置。配置包含的凭据须保持本地；这不是新 MCP 实现。目前还需可分发的插件安装包、许可证确认和干净机器安装验证，才能去掉开发者配置步骤。

## 删除图片或项目

图片缩略图右上角的 **×** 可以移除图片；左侧会话 **右键 → 删除会话**。点击后移入本机 **回收站**，可以恢复。删除或恢复参考图后需要重新整理并批准计划；已有 SU 模型不会被清空。建模回合运行时删除不可用。项目删除会收起本机项目文件，若该模型仍在 SU 中打开，请先关闭它，再连接其他项目。

## 聊天附件与执行步骤

发送图片后，缩略图进入对应的用户消息，输入框只显示未发送的新图；已发送图继续留在项目和模型上下文中。消息图片右上角 × 也可移入回收站。建模步骤显示 API 实际响应、文件写入、模型修改提交、截图回读；写完脚本不会被当成已经建模。静态「已配置」不等于供应商刚刚响应，截图存在也不等于还原质量通过。
