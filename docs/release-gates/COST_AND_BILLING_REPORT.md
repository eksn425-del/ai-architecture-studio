## 对客账本与上游账单

- 平台服务器持有供应商密钥。每个模型请求先按运营配置预占，经模型身份和终端用量核实后，根据任务记录的计价版本写入 K Studio 额度。未知、异常或超出预占的费用进入待核对，保留预占。
- 同一自然语言建模回合可产生多个模型请求。当前回合标识由客户端生成，原项目回合共享累计限额。服务端同时评估单日用量、每用户未完成请求、钱包余额和全局并发。供应商货币成本另按真实账户的输入、输出、缓存、时段、失败与优惠核对。
- BYOK 模型费用由用户直接向供应商支付。K Studio 软件服务费使用独立开关和授权规则，默认关闭。本机 token 用量仅供使用分析。只有云端确认的费用事件可写对客账本。
- 候选报价结构按平台模型消耗和软件服务费列项，BYOK 独列软件服务。经营者确认正式价格和失败补偿前保持收费关闭。真实 staging 应用供应商实际账单计算成功交付的可变成本，包括成功、失败、重试、审查和基础设施，公布费率供测算。 [B.AI 定价和用量](https://docs.b.ai/zh-Hans/llmservice/pricing-and-usage/)

## 真实验收所需输入

授权独立 staging 运营模型账号和有限测试预算，确认商用服务范围。私密配置使用 `KSTUDIO_BAI_PLATFORM_KEY`、`KSTUDIO_CLOUD_MODELS`、`KSTUDIO_CLOUD_PRICES`、`KSTUDIO_PRICES_CONFIRMED` 和 `KSTUDIO_GLOBAL_MAX_CONCURRENCY`。按运营账户的真实模型清单和账单核对实际路由及费用。商户材料和一次真实小额付款及原路退款由负责人另行批准。 [B.AI API 参考](https://docs.b.ai/llmservice/api/) · [G06](G06/verdict.json) · [G07](G07/verdict.json)
