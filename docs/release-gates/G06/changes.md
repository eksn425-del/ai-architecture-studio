# G06 实际改动

- 网关规范化每个模型请求并写入账户隔离的请求摘要。SDK 缺独立请求 ID 时由建模回合与请求内容确定账本标识。回话密钥轮换后重复提交仍返回原任务。显式键与不同请求内容冲突时拒绝发出请求。
- 平台仅接受本地函数工具。Responses 请求指定禁止持久保存。记录最小供应商请求标识、响应标识和用量。客户可见自己的输入、输出、缓存用量。刚通过官网认证的管理员可读取上游对应信息，只能对待确认任务按明确原因和额度提交对账。
- 按事件分帧解析 SSE。Responses 需要明确完成状态、预期模型和终端用量。Chat 需要结束原因、完整用量事件和终止事件。回执和余额先持久化，再向客户端发出成功终端。未知、超出预占或断流的尝试保留预占。
- 未派发的过期预占以一个事务释放并写入账本。已运行任务按网关允许的最长时限和恢复余量处理，防止维护进程提前接管。重启不会把可能已派发的请求重送。账本审查从数据库同一查询快照读取。
