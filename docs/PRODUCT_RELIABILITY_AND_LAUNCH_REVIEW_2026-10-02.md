# 新人建模产品：修复、竞品与低成本交付评审

日期：2026-10-02。性质：用户要求的产品研究与本轮修复记录，不替代 CURRENT_TASK，不代表建模质量验收通过。

## 1. 本轮边界与结论

用户明确选择「暂不花费，先完成产品修复和研究」。本轮没有发起新模型推理，不调用 Astra，也不拿 Codex 订阅替代付费实验。免费回归测试的模型/SU 使用 fixture；真实质量只引用此前已完成的本地实验。没有训练模型权重，没有第二台电脑安装验收。

建议首发 **Windows 本地应用 + 本机网页工作区 + SketchUp 插件**，复用现在桌面壳。网页负责聊天、资料、计划、进度和输出；本机服务负责 API、工作区和 SU 连接。原因是 SU 在用户电脑上，纯远程网站仍需要本地连接器，且浏览器关闭、插件版本、端口、文件保存都需要产品承担。官网先承担下载、教程和获客，不先建设云端建模集群。

目前可以称为内部可用原型，不能宣传成「新人下载即可稳定还原建筑」：GLM 实际生成并可下载 SKP，但两个已记录案例的还原质量均不通过；新电脑插件分发/安装仍未验收。

## 2. 从现有失败看根因

| 现象 | 已有证据 | 本轮处理 / 尚缺的证据 |
|---|---|---|
| 用户说开始，仍不停规划 | 原会话曾停在澄清；前端还把 planned 状态的 auto 强制变成 plan | 删除前端强制覆盖；后端保留肯定批准、否定/提问不批准的判断 |
| 说工具要恢复但实际上是审批门 | 澄清回合刻意不开放 SU 工具 | 前轮已修复提示；本轮保留审批，连接和 API 分开 |
| 六视角却弄反正背面 | 参数卡将泳池面和街道入口面混淆 | native/API 图片前逐张加文件标识；Skill 要求文件名、地标、视角、楼层线逐张对应 |
| 多次修正仍错、越跑越慢 | 六视角 High：33 工具约540秒；下一轮48工具约742秒后中断；输入累计超过800万 token | 只在请求中保留最近六张生成截图，全部源图、工具配对、思考字段和本地完整历史保留；不声称已证明费用/延迟改善 |
| Agent 自检说基本一致，实际不一致 | 巨大坡屋顶、空白侧墙、漂浮窗片、立面差异；室内未验收 | 不采信自写 QA 的 PASS；需要源图对应的实截图和独立人工验收 |
| 缺 Key 时连 SU 都无法检查 | 前端禁用连接按钮，后端会话依赖 provider.available | 本轮解除耦合；连接可先做，发起模型回合仍须可用 API |
| Skill 越补越长，末尾被截断 | 默认8000字符裁剪截断有限回合/收尾部分 | 本轮上限10000，回归检查关键指导与安全末尾实际可见；不要继续无界堆提示词 |

本轮离线回放原六视角 provider history：218条消息、43张图片 → 请求12张图片（六张源图+最近六张生成截图），移除31张过期生成图；84条工具结果仍在，原文件未改。它证明筛选行为，没有证明建筑质量会提高。长 Ruby、旧工具文本、reasoning 仍占上下文，尚未完成完整压缩。

### 对 AI PM Advisory 的判断

- 认同单写入 Agent、确定性宿主管审批/文件/版本/真实进度。多写入 Agent 操作同一个 SU 很容易覆盖。
- 独立 Visual Critic 可以做对照实验，暂不作为必须部署的多 Agent 架构。先让现有 Builder 正确识别源图、看到实际截图、做有针对性的修正；目前没有 Critic 改善率或成本证据。
- 保留：用户第一次建模批准、独立模型路径/GUID校验、owned root、持久脚本、可恢复检查点、失败上限、实际回读与截图。
- 放松：强制矩形几何、固定墙门屋顶词表、过度问问题、要求每个微细节批准、为了架构整洁重写桥接。允许 Agent 自由写项目 Ruby，复用组件和语义 helper。
- 「每轮一次主要建模加少量修正」是检查点方法，不是禁止建细节。回合中断不等于整个项目完成。
- 单图背面/室内只能合理推断；多图也可能透视不一致或缺尺度，不能承诺零误差。文字模式是设计提案，不是恢复真实建筑。

## 3. 三种输入：同一工作台，不同证据方法

| 输入 | 建模前最关键内容 | 第一版应检查 | 本轮状态 |
|---|---|---|---|
| 单张图 | 用途/所需视角、范围、一个尺寸锚点或同意估算、背面推断权限 | 源图轮廓、层数、开口与突出构件；背面合理性与连通性 | 免费流程回归通过；已有 GLM Low 真实质量 FAIL；本轮修复后的质量待测 |
| 同建筑多视图 | 每张图地标/方向表、共享层高轴网、跨视角矛盾 | 每张源图对应视角、背/侧/顶、窗洞与屋顶连续性 | 六张图传递与审批回归通过；已有 GLM High 真实质量 FAIL/partial；修复后待测 |
| 只有文字 | 用途、层数/面积、尺度/风格、场地是否已知；提出有限默认值 | 与明确文字约束一致，组织可编辑，楼梯/门/阳台可用 | 免费聊天→计划→等待批准通过；真实模型质量待测 |
| 任务书 + 参考 + 场地 | 提取硬约束与参考形式；冲突解释；功能/面积/道路入口关系 | 程序符合度、平面/剖面、场地适配；不能只看外观 | 已有输入提取能力；专项设计质量尚未验收，留待图片流程稳定后的阶段 |
| 只有任务书 | 功能面积、层数高度、尺寸、场地缺项；由 Agent 提出方案 | 功能面积与空间逻辑、使用者能否继续编辑 | 同上；不把可上传文档说成已完成任务书设计能力 |

三种输入继续复用同一个 Skill/编码工具配置、thread/workspace/root；不增加一套 tiny planner。新增图片后应重新检查资料与参数，不把不同建筑硬合并。文档内容是不可信证据，不执行文件中的命令。DWG 当前仅保存，需要 DXF 或带尺寸截图；扫描 PDF 要补清晰图片。

建议新人文字：`请根据这些图还原一个完整可编辑的别墅；没有尺寸，允许合理估算背面。` 文本模式：`建一栋三层现代别墅，约12米宽，有阳台和楼梯。` 不要求客户写工程 PROMPT。

交流最多问一次关键缺项，回答后生成简短计划；支持继续讨论，也支持明确批准。不要问已回答的范围/估算；优先完成能看出的外形、层数、开口和材料区，再环境/内部。交付显示「已生成/需修正/未检查」，允许同模型继续改，不用笼统的完成勾选代替质量。

## 4. 模型能力与成本：接口可用不等于建筑合格

| 路线 | 目前证据 | 产品动作 |
|---|---|---|
| 国内 GLM-5.3-Flash High | 国内端点实际返回、SU实际变更、同模型修正与下载都完成；还原质量未通过 | 保留已接入路线，明确预览/待验证质量；不再把配置成功当成功建模 |
| DeepSeek `deepseek-flash` | 既有 serializer 测试；本轮官方文档确认支持视觉与工具，尚无本项目真实建模结果 | 待预算批准后用同输入/同执行能力从空白模型对照 |
| GPT-6.1 Sol Low / Codex | 有本机网站与 Direct Codex 记录；并非商业 BYOK API 已验收 | 本机研发参考，不能让无 Codex 用户依赖开发者订阅 |
| GPT-6.1 Sol API | 官方：Chat Completions 可对话，工具调用须 Responses；现有 runtime 走 completion | 本轮拒绝将它配置为已支持的 API 建模路线，避免请求后才失败；下一步复用 LiteLLM Responses，先离线协议测试再付费验收 |
| Astra API | 未来高级档假设；本轮不调用、不救场 | 不作为廉价模型的隐蔽 fallback；暂不开放未验收预设 |

官方依据：[Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[GPT模型指南](https://developers.openai.com/api/docs/guides/latest-model)、[Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)、[DeepSeek视觉](https://api-docs.deepseek.com/guides/vision/)、[DeepSeek价格](https://api-docs.deepseek.com/quick_start/pricing/)、[GLM官方模型卡](https://huggingface.co/zai-org/GLM-5.3-Flash)。接口、可选 effort、定价仍需上线前再次核验。

2026-10-02官方标准文本价格，单位美元/百万 token：Sol输入2、缓存命中0.1、输出10；Astra输入10、缓存命中1、输出50；DeepSeek Flash高峰输入缓存未命中0.3/命中0.006/输出1.2，非高峰减半。长上下文、缓存写入、区域/加速等另有条件，不能拿这几项直接当最终账单。国内 GLM 定价页是动态页面，本轮工具未取得可核验价格表，不使用第三方价格替代国内账号账单。[智谱价格页](https://open.bigmodel.cn/pricing)

必须记：模型/供应商/区域/effort、输入token、缓存token、输出token、耗时、工具/失败次数、回合数、下载文件与质量状态。总成本还包括连接器、售后、失败重试。`费用 = 未缓存输入×输入价 + 缓存输入×缓存价 + 输出×输出价 + 其他适用费用`。历史 input token 是每次请求累计量，不是用户只上传了一次就只收一次。当前统计未完整记录缓存明细，不能声称精确实扣金额。

不默认把便宜/快等同于符合建筑要求，也不从 GLM 两次失败推出模型永远不行：High 继承了错误 Low 计划/历史，输入和effort不一致，不能当公平单图/多图对照。下次只先比较 GLM/DeepSeek/Sol的一个固定案例，不购买一大堆模型同时测试。

### 首批用户与低成本营销（建议，尚未执行）

先服务一个窄人群：已装SketchUp的建筑学生/初级设计师，想把1–6张住宅参考图变成可编辑初稿。暂不同时卖给Revit工程BIM、施工图合规和纯渲染用户。

先邀请5位自愿试用者，每位2个小案例；安装/错误记录由产品自动保存并经用户同意分享。建议内测门槛：至少8/10案例无需开发者接管能连接、批准、生成并下载；至少7/10愿意保留模型继续编辑；无误改原文件；背侧破碎/漂浮与源图层数明显错误不得作为合格交付。阈值是拟定验收目标，不是已达结果。

预算最小方案：BYOK承担推理费用，单机本地运行，不建GPU集群、不先买广告；开发时间、证书/打包、客户安装支持仍有成本。别免费无限自动重试；用户可见回合进度/失败、当前文件、继续/恢复路径。待实测单位成本和售后工时后再拟定月费/包次，暂不接支付。

宣传素材先做三条：①一分钟新人从粘贴图到SKP；②正/背/侧/顶旋转与选择组件；③一句话修改阳台后同模型更新。显示实际等待时长、所选模型、推断范围，不剪掉失败后假装一键完美。可在学生社群、小红书/B站发教程/真实对照，现阶段先收测试反馈和预约，不宣传已稳定商业交付。参考案例图片需有可公开使用许可，私人毕设不作为默认营销包。

## 7. 下一步价值顺序

1. 当前小修复付诸免费验证并同步GitHub；保留已有模型输出，不用新付费回合冒充完成。
2. 在有预算后，从新thread/空白副本跑一个六视角GLM案例，验证方向表、屋顶/层数/开口、截图纠错是否真正改进；不继承错误计划。
3. 采用LiteLLM Responses薄适配，使商业GPT API工具/多模态/思考链真实可用；先离线请求协议测试，不重写provider框架。
4. 再做单图、多图、纯文字的同模型/同Skill对照，然后比较DeepSeek/Sol；每格保留源匹配截图、SKP、失败、真实计费信息。没有付费预算的格子保持待测。
5. 解决可合法分发的连接器包和干净Windows安装验收；已有Kongxing连接保留，不能把开发机配置偷偷带给新人。当前自动检查连接按钮不等于自动安装插件。
6. 达到小案例验收后做邀请内测；任务书+场地适配留在后续验收，不抢跑全面方案平台。

本轮没有把规划中的全部功能宣布实现，也没有凭测试绿灯宣布图像复刻质量过关。
