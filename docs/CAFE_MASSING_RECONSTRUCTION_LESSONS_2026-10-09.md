# 双视角咖啡店：体块遗漏与审查流程修复

## 真实失败

此前 [双视角测试](test-results/windows/2026-10-09-cafe-two-view-luna-max/README.md) 为 PARTIAL。两张来源图均可见右后较低白墙附属体及独立低屋顶，生成模型却主要是一座高盒体。该遗漏不能解释为不可见背面的合理补全。第二次修正用巨大植物屏遮模板人物，还挡住自行车与圆牌；这是错误的修正优先级。

SAIE 真墙洞、Ruby 写入、KEEP、下载重开成功，只证明执行与可编辑性，不能证明体块识别正确。没有控制变量的对照实验，不能据此断言 GPT-6 Luna 的能力上限；本次可以确认的是规划遗漏、Builder 实现错误及自审未拦截这些错误。

## 本轮修复

- 工作区 v12 增加 `notes/volume_inventory.md`：逐图列主/附体量、独立屋顶与雨棚、连接关系、高低关系、可见比例依据、置信度及实际对象路径。不得用一个主盒体概括全部建筑。
- Native 宿主截获提交视觉审查，在全新上下文启动同模型独立 Critic；传入真实来源整图、当前六方向和来源角度结果。Critic 无动态 SketchUp 工具，沙箱只读且无网络。宿主用 Critic 返回值覆盖 Builder 提议的结论；格式错误或调用失败不得降级为 Builder PASS。
- 优先检查缺失体量、屋顶轮廓与高度关系，其次门窗，再细节。禁止通过新增遮挡配景掩盖错误。
- App Server token 记录从线程累计总量提取本轮增量，避免恢复会话时计入历史总量；无可核实通知时仍为 null。记录计量范围，不能直接把不同流程的数值当作降本证明。

体量清单是工作指导，不是几何硬编码或自动证明。独立 Critic 仍可能判断错误，因此保留人工逐图审查和 PARTIAL 状态。

本轮第二次修正还暴露 KEEP 解释错误：Critic 要求改变屋顶坡度，同时建议保留屋顶材料/组合；Builder 将后者映射为冻结整个旧屋顶，再加一层新屋顶，造成重复檐边。已补充 Critic/Builder 指引：保留材料风格不等于锁定待修构件尺寸，不得用重复几何绕过 KEEP。这条新增指引在本轮完成几何后补充，尚需下一轮真机验证；不能称当前叠层已经修复。

## ADAI 使用事实

上轮咖啡店启用了 ADAI 可选 helper，但咖啡店脚本没有调用它；实际使用 SAIE 墙洞和 Ruby。此前独立工程 smoke 调用 ADAI 不能算咖啡店使用。后续每个运行按脚本和工具记录报告实际调用；安装、启用、工具可见和实际使用须分别记录。矩形附属墙体与直线坡屋面可直接用已有 Ruby，不为获得 ADAI 标签增加调用。
