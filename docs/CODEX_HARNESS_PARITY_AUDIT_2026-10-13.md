## What is already genuinely shared

K Studio `app/native_agent.py` invokes the actual upstream `codex app-server`; registers host-scoped dynamic SketchUp tools; sends original localImage file paths in upload order; maintains an isolated workspace, project files and ProjectRuby single guarded writer; records thread/turn and real model/effort/usage; uses separate read-only visual reviewer. Consequently "there is no Codex harness" and "the model never receives images" would be false.

## Why native Codex + SU MCP can work better than the site

| Native open-source mechanism | K Studio current behavior and specific failure hypothesis |
| --- | --- |
| History/context manager, compact checkpoints and resumable thread | After any committed Ruby state `native_agent._run_turn` intentionally starts a new thread, relying on limited project notes and recent conversation. This saves history tokens but loses unpreserved spatial reasoning and actual tool traces; 2026-10-12 Medium repeat-planning remains a plausible consequence, not proven causation. Do NOT blindly resume every giant prior thread: preserve compact, verified critical state. |
| Tool router/registry + sequential tool-result feedback | Site uses actual App Server, but additionally restricts discovery to reconstruction-only tools and imposes a host writer/reviewer gate. This is prudent for single-writer model identity, but repeated independent review from an empty per-turn `quality_state` makes a valid SAME revision look unreviewed. In the real Medium owner continuation, first write attempts were refused for no current review in both turns; one correction then 73 tools/3.400632M input/visual FAIL. |
| Image preparation and multimodal context | Site does send localImage sources each turn in `_app_server_turn_input`; problem more likely in source-to-3D plan/angles and tool feedback than missing images. Do not infer Codex uses an undocumented visual model trick. |
| Persistent worktree with AGENTS/skills and model-directed execution | Site seeds `app/codex_parity.py` workspace but also injects roughly 20k of task Skill and fixed stage/review instructions. More instructions cannot replace calibrated primary-form/spatial intent and source-angle comparison. |
| Host policy separates permissions and model autonomy | Keep one SketchUp writer, exact owned scope, approved plan, source/KEEP and budget; prune redundant checks without opening raw whole-model commands or private source access. |

## This iteration: concrete independent-review continuity

1. Persist SHA-256 over all actual source files, six current PNGs AND sidecars, current source-matched pair image/sidecars, and reconstruction-evidence note at the instant a review is accepted. Preserve old receipt/history semantics.
2. A NEW builder turn may reuse a prior dedicated read-only NEEDS_FIX review **only** when the last append-only history matches, all current host-verified Ruby revisions and actual six view provenance still match, complete original source-angle coverage holds, current source inventory has not changed, and all SHA hashes still match. Legacy/no-hash, malformed, Builder self-review, changed photo/capture/sidecar/ledger/revision fail closed and require new trusted review. New geometry invalidates cached review immediately; an accepted verdict is not reused to block a new user goal.
3. Inject a bounded three-issue source/spatial checkpoint into the new Builder's prompt, clearly marked advisory data, not tool commands. Let the user make a short natural request instead of needing an engineering message. If new human intent requires changing old KEEP, re-review explicitly rather than secretly bypassing the host protection.
4. Check cache again at the write boundary, not just turn start. This removes unnecessary SAME-revision repeat QA; the final current-version six-view and source-matched independent Critic after an actual write still remain mandatory. **Current state: code/CI preparation only, not new native visual PASS.**
