# Reusable Blender assemblies and bounded quality checks

Base: published trial code `965eb67`. This is a reconstructed engineering iteration after the previous shared workspace was unavailable in the current mount. A preserved private model checkpoint was reopened and corrected again; it is not claimed to be a recovered later model revision.

## Changes
- Bounded parameterized wall openings, sloped closures, slab openings, plants, furniture and stairs are reachable through K Studio's normal Blender tool surface.
- Component preparation is read-only. Exact prior component receipts remove stale children; unrelated ID collisions are rejected. Replacement/removal must include legs and frames, not only the visibly prominent part.
- Six axis review cameras fit current world bounds. Explicit perspective cameras and labeled render-only cutaways are supported. Cutaways are excluded from the ordinary full-model preview list.
- Explicit connection audits distinguish contact, signed gaps, misalignment and positive bounds overlap. Mesh bounds retain a surface-verification warning.
- Declared circulation zones report positive-volume box blockers and conservative mesh candidates. They do not certify navigation, accessibility or building-code compliance.
- Ordinary corrections remain within the existing finite stage budget and plan-approval gate. First-turn quality must be judged separately from subsequent design wishes.

## Actual model checks
The private villa was processed through K Studio conversation planning, approval and tool dispatch using an explicitly assistant-authored deterministic simulated provider. This reconstructed iteration uses actual application routes and tool dispatch headlessly; it does not claim a new browser-click acceptance run. Blender saved and independently reopened the editable native model. No external model inference was used.

- Roof/wall closure and window-frame corrections were checked in actual native geometry and multi-view renders.
- A confirmed 5 cm roof-cap/wall overlap and 10 cm wall/column gap were corrected; three declared final junctions have zero signed gap and zero bounds overlap.
- Four perimeter corners have zero measured gap and zero positive overlap in the scoped boxes.
- Seven sloped roof-contact checks differ by less than 2 micrometres in Blender's float readback.
- Six declared aisle, stair-entry, kitchen and storage clearance zones are unobstructed under the stated box/mesh-bound method.
- Before the final garden/material pass, 405 pre-existing exterior objects were unchanged. The bounded final garden pass preserves the geometry of all 581 pre-existing non-tree objects; 342 original exterior objects also retain identical materials. The intended exceptions are the stair-opening slab, inferred lower rear/side windows obsolete indoor-table parts and four targeted front roof/wall/column pieces.
- Added outdoor chairs/cushions, table supports, stepping stones and six plants; moved and raised one complete tree assembly, and separated wood/fabric/glass materials. These improve visible completeness but remain schematic.
- Visual review found dangling obsolete table legs that clearance boxes did not catch. The legs were removed, stair handrails added, and complete-component removal/kind-change regression tests added.
- Actual independent small cases exercise window replacement 2→1→0, a translated model camera, all six furniture kinds, stairs and a slab opening, including native save/reopen.

## Limitations
There is one unique source view. Rear elevations and interiors are proposed coherent design, not observed original truth. Interior scope is living/dining/kitchen, loft sleeping/study/storage and stairs; it is not a fully specified residential program or construction document.

The simulated provider demonstrates integration and geometry mechanics, not autonomous first-turn vision/reasoning quality. The final local SketchUp test must use the owner's chosen new single image and record first, second and third rounds separately. Cloud Blender checks do not certify SketchUp parity.

Final rendering uses 128 exterior samples and 256 interior samples. Native CPU previews can retain sampling noise because this Blender build lacks OpenImageDenoise. The renderer now checks capability before enabling it. The initial denoising failure and subsequent actual successful renders are preserved privately.

Private references, models, screenshots, raw runtime logs and simulation fixtures are not included in this code publication. Final test totals and native results are recorded in RESULTS.json after the final exact-tree run.
