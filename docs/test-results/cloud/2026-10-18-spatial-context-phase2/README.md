# Contextual attachment intent and bounded spatial audits

Base: 5f48741e6573d1fa88d88822c950d528432d025a. This phase leaves the first release unchanged and adds the following bounded capabilities.

## Attachment intent

The same independent read-only native conversation interpretation can propose roles for host-identified attachments using the actual current user text and source history. Each image is bound to its source path, byte hash, original turn and model revision. No filename guesses or fabricated visual observations are treated as evidence. The interpreter must quote supporting current-user text. This interprets intended use, not the pixels' semantic content.

Only fresh automatic roles or explicitly pending unresolved automatic roles can change. User-selected roles and resolved historical evidence remain protected. Identical historical defect pixels cannot become target truth or acquire the new model's revision. A role change invalidates the old plan. Unknown attachments sent during a clarification remain eligible for the later answer, so the user need not manually select every image. Ambiguity still asks; language interpretation is not guaranteed error-free.

## Native spatial evidence

New SU tools invoke guarded inspect_owned themselves; callers cannot supply their own native receipt. Evidence binds model path/GUID/root/script/revision and rechecks identity after inspection. Existing SU evidence is parent-local AABB only: same-parent gap/contact is a proxy; cross-parent transforms, solid overlap, world-scale correctness and full walkability remain unverified. No actual SketchUp process ran in this cloud test.

Blender adds declared empty-volume clearance and adjacent top-endpoint checks for contact, width and height differences. Exact axis-aligned boxes can satisfy those specific checks; meshes and incomplete inventories remain bounded candidates. These are not arbitrary BIM, building-code compliance or full navigation certification.

Declared audit checks automatically rerun after committed writes. Audit failure explicitly reports geometry_already_committed and unverified, never automatic rollback. SU post-write results are appended to the model-visible tool text.

## App Server transport correction

Internal structured tool receipts are normalized at the native JSON-lines boundary into success/contentItems. Existing legal contentItems remain intact. This also fixes the earlier bare Blender receipt boundary. Mock protocol tests verify actual serialized responses; no live model call was made.

## Actual Blender verification

The AgentToolSurface fixture built and saved a generic stair/platform/corridor/rail system, declared relation repairs and spatial checks, then performed one bounded edit. Native gap checks of roughly150/100/50mm closed within0.01mm. Two stair/platform/corridor endpoints changed from needs_fix to satisfied_endpoint_proxy; declared landing clearance remained clear. Seven KEEP objects and the initial native file stayed unchanged. Saved files were freshly reopened, and before/after renders were inspected and retained privately.

Provider calls: zero. Actual GUI remains blocked by isolated loopback namespaces (service HTTP200 within its execution context, normal cloud browser connection refused). Actual SU and the owner's original building/image fidelity are NOT_RUN. Private models, images and raw event logs are excluded from publication.
